# Actions write their own access log entry

The access log records every read of a customer's data by anything other than that customer's own page views. We could have recorded reads inside the customer data layer (ADR 0004), so every query logs itself. We didn't, because the data layer can't tell why a read happened, and a single sweep check or Mission runs many queries that belong in one entry. Instead each action writes one access log entry, naming who, what, why and when, in the same transaction as the rest of its writes. The sweep check, each Mission, each Standing search check, each Sync, link, unlink and Export do this. Nothing ever removes an access log entry, even Close and delete.

The cost is that a new action can forget to log. `src/hard-rules.test.ts` fails any module that writes a Decision log entry, a Finding or a Mission ending without also writing an access log entry. The check lists its exceptions by name: the modules that record only a change the customer made, such as a setting edit, an Undo or a picked Option, because the customer's own action is not a read by someone else.
