# Settle-up payments post one pair per customer, and Groups are shared records

A Settle-up payment moves money between two Plinth customers. One ledger transaction with four entries across both customers would break ADR 0004, because one write would span two customers' scopes, and it would break the single-pair rule. Instead, each side posts its own single-pair ledger transaction against the Plinth transfers clearing account, through its own customer's scope. Both use one transfer id in their idempotency keys and post in one database transaction, so the clearing account nets to zero and neither half posts alone. Payments to and from Outside contacts use the Instant transfer clearing account, like any other outside institution.

A Group and its Shared costs belong to no single customer. They are shared records, and code reads them only through one function in `src/customer-data.ts` that first checks the reader is a Member. A Member sees the Group's Shared costs, Shares and who owes whom, never another Member's balances or accounts. A Member viewing their own Group is a page view and writes no access log entry. The agent reading Group data for the Split rule or Shared cost spotted writes one entry in its own customer's access log (ADR 0010).
